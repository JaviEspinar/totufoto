Imadive 0.2.0 tidies up the gallery's HTTP API before more programs start using it. For people using the app nothing changes: your folders, names and index carry over, and the page works as in 0.1.12.

## Downloads

- **Windows 10/11**: `Imadive-0.2.0-windows-x64.exe`. Double-click it. It is not signed, so the first time Windows may show "Windows protected your PC": click **More info**, then **Run anyway**.
- **Linux (x86-64)**: `Imadive-0.2.0-linux-x86_64.AppImage`. Run `chmod +x Imadive-*.AppImage`, then start it. If it says FUSE is missing, install `libfuse2` or run it with `--appimage-extract-and-run`.

Your folders, people names and index carry over from earlier versions; nothing is indexed again.

Each download can be checked: `SHA256SUMS` lists the files' checksums, and every file carries a signed record of the GitHub build it came from (`gh attestation verify <file> --repo JaviEspinar/totufoto`).

## What's new

- **Screenshots** in the README, of a library of public-domain colour photos from the Library of Congress (1940 to 1943).
- **Thumbnails after rotating**: Optimization could keep showing a photo the way it was before you rotated it. A photo's version is now part of its thumbnail's address everywhere, so a browser can't keep an old one.

## For scripts using the API

If you only use the gallery in a browser or the desktop app, you can skip this. Scripts that call the API need these changes (details in [docs/api.md](https://github.com/JaviEspinar/totufoto/blob/main/docs/api.md#changes-in-02)):

- Removing a photo: `DELETE /api/photos/{id}?from=gallery` (or `from=disk`), instead of `POST /api/photos/{id}/remove`.
- Removing a folder: `DELETE /api/folders?path=...`, instead of `POST /api/folders/remove`.
- Showing photos removed from the gallery again: `DELETE /api/excluded`, instead of `POST /api/excluded/clear`.
- Renaming or hiding a person: `PATCH /api/people/{id}`, which now always answers with the person.
- Thumbnails: `/thumb/{id}/{version}`, instead of `/thumb/{id}?v={version}`.

From now on the API changes only in versions like 0.3, never in versions like 0.2.1.

## For people building it

- The page's script is now ES modules in `web/js/`, one per area, still with no build step. A check in CI makes sure they load in an order that works.
- A browser test opens every tab and fails on any script error.
- Updating a server: `git pull`, `cargo build --release`, then restart the service.
