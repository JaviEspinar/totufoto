Imadive 0.3.4 shows the People tab in two parts, gives uploads more feedback and control, and keeps the gallery running when a folder or a file can't be read.

## Downloads

- **Windows 10/11**: `Imadive-0.3.4-windows-x64.exe`. Double-click it. It is not signed, so the first time Windows may show "Windows protected your PC": click **More info**, then **Run anyway**.
- **Debian, Ubuntu and Linux Mint** (Debian 12 or Ubuntu 22.04 or newer): `Imadive-0.3.4-linux-amd64.deb`. Install it with `sudo apt install ./Imadive-0.3.4-linux-amd64.deb`, then start Imadive from the applications menu.
- **Other Linux distributions (x86-64)**: `Imadive-0.3.4-linux-x86_64.AppImage`. Run `chmod +x Imadive-*.AppImage`, then start it. If it says FUSE is missing, install `libfuse2` or run it with `--appimage-extract-and-run`.
- **A Linux server** (x86-64, or ARM64 such as a Raspberry Pi 4 or 5): `Imadive-server-0.3.4-linux-x86_64.tar.gz` or `…-linux-aarch64.tar.gz`, installed by the one-line command in the [server guide](https://github.com/waiting4timeout/imadive/blob/main/docs/server.md).

Your folders, people names and index carry over from earlier versions; nothing is indexed again.

Each download can be checked: `SHA256SUMS` lists the files' checksums, and every file carries a signed record of the GitHub build it came from (`gh attestation verify <file> --repo waiting4timeout/imadive`).

## What's new

- **The People tab comes in two parts**: *Classified*, the people you have named, and *Not classified*, the groups without a name yet — always with the most photos first, so the people who matter most come up first. Click a face to see that person's photos: it shows only them, clearing the filters set before. To combine a person with other filters, tick them in the *People in the photo* column instead.
- **Uploads from a phone**: *Choose files* opens the file manager, where a whole folder can be picked at once (open DCIM › Camera, for example, and use *Select all* in its menu). Files that aren't photos or videos are left out.
- **Uploads with more feedback and control**: the card says what is happening from the moment you choose, while the names are checked before anything is sent. When some files have the same names as ones already in `imaDive-uploads`, a dialog asks what to do with all of them: *Skip* them, *Overwrite* the ones there, or *Keep both* (the new one is saved with a number, `photo (2).jpg`). A file exactly the same as the one there is never copied twice, whatever the choice. Files that couldn't be uploaded (a connection lost, say) are listed with the reason, and *Retry the ones that failed* sends them again.

## Fixes

- A folder given on the command line that isn't there when the gallery starts (a drive not mounted yet) no longer stops it: the gallery starts, shows the folder as *not available* in Settings, and finds it at the next scan.
- A folder or file inside the library that can't be read during a scan (a disk or filesystem error) keeps its photos in the gallery; the log names it, and a later scan reads it again once the disk does.
- In the browser's folder picker, a path typed while the folder list loads isn't overwritten by it.
